# Convolutional Codes and Turbo Codes

## L0 — One line
A convolutional code is a linear shift-register filter whose valid outputs form a trellis, and a turbo code joins such codes (often two) through permutations and decodes them by passing messages between their trellises.

## L1 — The gist (≤ 120 words)
How can a stream of source bits be turned into a protected transmission with a shift register, and how can it be decoded? Convolutional codes come from linear-feedback shift registers (systematic or not, recursive or not). They are decoded on a trellis with the sum–product (BCJR) algorithm for bit posteriors, or the min–sum (Viterbi) algorithm for the most probable path. A turbo code uses constituent convolutional encoders (often two) linked by interleavers (permutations). It is decoded iteratively, with messages passed between the two trellises. Turbo codes perform excellently down to error probability about $10^{-5}$, but randomly built ones tend to have an error floor caused by low-weight codewords. Unpunctured ones have sparse parity-check matrices.

**Prerequisites:** binary (mod-2) arithmetic; trellises and the forward–backward and min–sum algorithms (Ch. 25); linear block codes and parity-check matrices; octal numbers; the idea of an impulse response (output for a single 1 input).

## L2 — Key ideas
- A convolutional code is generated by a shift register (in this chapter: $k$ memory bits, one input, two outputs, rate 1/2). It comes in three flavours: systematic nonrecursive, nonsystematic nonrecursive, systematic recursive (pp. 574–576). Systematic means a source bit is copied to an output; recursive means the register has feedback.
- Tap vectors (which register bits feed an output) are written in octal; a recursive code is named by an octal ratio, e.g. $(247/371)_8$ (pp. 575–576).
- A systematic recursive code and a nonsystematic nonrecursive code with the same taps define the same set of codewords, but the encoders behave differently: finite versus infinite impulse response (the output for an input of a single 1) (p. 576).
- Decoding uses the sum–product (BCJR) algorithm for per-bit posteriors, or min–sum (Viterbi) for the most probable state sequence (p. 578).
- Plain convolutional codes protect source bits unequally; this motivates terminating the trellis (returning the state to zero), which slightly reduces the number of source bits per codeword (p. 579).
- A turbo code has constituent convolutional encoders and $K\times K$ permutation matrices (interleavers). Its factor graph has two big trellis nodes, and it is decoded by iterating sum–product between them (pp. 579–580).
- A stopping criterion based on consistent most-probable paths saves time and flags detected failures (p. 580).
- Randomly built turbo codes tend to have an error floor from about $10^{-5}$, caused by low-weight codewords. Low-density parity-check (LDPC) codes rarely have floors, provided their number of weight-2 columns is not too large (p. 581).
- Convolutional and (unpunctured) turbo codes have sparse parity-check matrices, so they are special cases of LDPC codes (p. 581).

## L3 — Walkthrough

### 48.1 Introduction (p. 574)
Block codes were described by a generator matrix, a parity-check matrix, and a trellis. The author omits the algebraic approach, partly because state-of-the-art codes make little use of it (p. 574). Convolutional codes are described in two ways: as mechanisms producing transmission $\mathbf t$ from source $\mathbf s$, and as trellises of valid transmissions (p. 574).

### 48.2 Linear-feedback shift registers (pp. 574–577)
The source stream goes through a linear filter. The filter has a shift register (bits $z_1\dots z_7$ in the box; its memory, also called its *state*), linear output functions, and possibly linear feedback. Bits roll right to left (p. 574).

All three filters in Fig. 48.1 take one source bit per clock cycle and emit two bits $t^{(a)},t^{(b)}$. The transmission is $t_1^{(a)}t_1^{(b)}t_2^{(a)}t_2^{(b)}\dots$, so the rate is 1/2. With $k=7$ memory bits these are *constraint-length 7* codes (pp. 574–575).

**Systematic nonrecursive (Fig. 48.1a).** No feedback, and $t^{(a)}=s$ (systematic: source bits appear unchanged in the output). The bit $t^{(b)}$ is the mod-2 dot product of a tap vector $\mathbf g^{(b)}=(1,1,1,0,1,0,1,1)$ with the state vector $\mathbf z=(z_k,\dots,z_1,z_0)$. Here $z_0$ is the bit that enters the memory on the next cycle. $g^{(b)}_\kappa=1$ wherever there is a tap from $z_\kappa$ (p. 575). Taps are written in octal by grouping bits in threes: $11\,101\,011\to 3,5,3$, so this code uses $353_8$ (Table 48.2, p. 575).

**Nonsystematic nonrecursive (Fig. 48.1b).** No feedback; both outputs use tap vectors $\mathbf g^{(a)},\mathbf g^{(b)}$, here $(247,371)_8$. Nonsystematic codes *can* have better error-correcting ability than systematic nonrecursive codes of the same constraint length (p. 575).

**Systematic recursive (Fig. 48.1c).** The taps that formed $\mathbf g^{(a)}$ now make a signal fed back into the register together with the source bit. $t^{(b)}$ is a linear function of the state as before, and $t^{(a)}=s$. It is named by an octal ratio, $(247/371)_8$ (p. 576).

**Equivalence.** The filters of Fig. 48.1b and c are *code-equivalent*: they define identical sets of codewords. For every codeword of one there is a source stream for the other giving the same output (p. 576). Proof, using the smaller $k=2$ filters of Fig. 48.3 (p. 576):

- Let $p=\sum_{\kappa=1}^{k} g^{(a)}_\kappa z_\kappa$.
- For equal transmissions, the systematic encoder's source bit must be $s=t^{(a)}$ on every cycle. It remains to check that its register then follows the same state sequence, assuming the states match initially.
- In the nonrecursive filter, $$t^{(a)}=p\oplus z_0^{\text{nonrecursive}}\tag{48.1}$$
- In the recursive filter, $$z_0^{\text{recursive}}=t^{(a)}\oplus p\tag{48.2}$$
- Substituting for $t^{(a)}$ and using $p\oplus p=0$: $$z_0^{\text{recursive}}=z_0^{\text{nonrecursive}}\tag{48.3}$$

So any codeword of the nonsystematic nonrecursive code is a codeword of the systematic recursive code with the same taps (p. 576).

*Intuition note:* In the recursive encoder the feedback sum $p$ cancels itself ($p\oplus p=0$). Whatever bit the nonrecursive register would take in, the recursive one computes the same bit from the source bit and the feedback sum $p$. So, if the two registers start in the same state, their contents agree at every step.

**Different behaviour.** The nonrecursive encoder has a *finite impulse response*: for input all zeros except one 1, the output has finitely many ones, and the register returns to all-zero (Fig. 48.4a). The recursive encoder has an *infinite impulse response*; in Fig. 48.4b the response settles into a period of three clock cycles (p. 576). In general a linear-feedback shift register with $k$ memory bits has an impulse response periodic with period at most $2^k-1$ (the maximum corresponds to the filter visiting every non-zero state) (p. 578). Cheap pseudorandom generators and cheap cryptographic products use such sequences, so some cryptanalysis problems are closely connected to decoding convolutional codes (p. 578).

### 48.3 Decoding convolutional codes (pp. 578–579)
The receiver infers the state sequence, and hence the source stream. The posterior probability of each bit comes from the sum–product (forward–backward, BCJR) algorithm. The most probable state sequence comes from the min–sum (Viterbi) algorithm (both from section 25.3) (p. 578).

Fig. 48.6 shows a 16-state ($k=4$) code, $(1,21/37)_8$, on a binary symmetric channel, with the received vector equal to a codeword with one bit flipped. Edges have three costs: 0 if they match both received bits (thick solid), 1 if they match one (thick dotted), 2 if they match neither (thin dotted). Min–sum finds the path of minimum total cost (p. 578).

**Unequal protection.** Fig. 48.7 shows two paths differing in only two transmitted bits, so the last source bit is less well protected than the others. This motivates *termination* (p. 579). In a terminated trellis (Fig. 48.8) the state returns to 0000 at the end. Four source bits are turned into parity bits, because the $k=4$ memory bits must return to zero, so slightly fewer source bits are carried per codeword (p. 579).

### 48.4 Turbo codes (pp. 579–581)
An $(N,K)$ turbo code has several constituent convolutional encoders (often two) and an equal number of *interleavers* ($K\times K$ permutation matrices). Without loss of generality the first interleaver is the identity. The $K$ source bits are fed to each encoder in the order its interleaver defines, and the output bits of each encoder are transmitted (p. 579). Often the first encoder is systematic (like the recursive filter of Fig. 48.6) and the second is a rate-1 nonsystematic encoder emitting parity bits only. The codeword is then the $K$ source bits, $M_1$ parity bits from code 1, and $M_2$ parity bits from code 2, giving rate 1/3 (pp. 579–580).

**Factor graph (Fig. 48.9a).** Two large rectangular nodes are trellises. The source bits and the first $M_1$ parity bits attach to trellis 1; the source bits and the last $M_2$ parity bits attach to trellis 2. Each codeword bit is in one or two trellises (parity or source bit). Each trellis is like Fig. 48.8 but about a thousand times longer (p. 580). To get rate 1/2, some parity bits are *punctured* (not sent; Fig. 48.9b) (p. 580).

**Decoding (sum–product, Ch. 26).**
1. Each trellis takes the channel likelihoods and runs forward–backward, giving each bit's relative likelihood of 1 or 0 given the other bits.
2. These likelihoods pass from each trellis to the other, multiplied by the channel likelihoods on the way.
3. Forward–backward runs again with the updated probabilities.

After about 10–20 iterations "it's hoped" the correct decoding is found (p. 580).

**Stopping criterion.** At each iteration, find the most probable edge at each time-step in each trellis. If these join into two valid paths that agree with each other, it is reasonable to stop, since further iterations are unlikely to move away from this codeword. If a maximum number of iterations is reached without this, report a decoding error. The author gives reasons: big time savings with no loss in error probability; detected failures are identified as such; and undetected errors give helpful insights into the code's low-weight codewords, which may improve the process of code design (pp. 580–581).

**Error floor.** Turbo codes as described perform excellently down to decoded error probability about $10^{-5}$, but randomly constructed ones tend to have an error floor starting there, caused by low-weight codewords. The author calls tweaking the construction a "black art" that never fully removes low-weight codewords; they can be eliminated only by sacrificing the excellent performance. LDPC codes rarely have error floors, as long as they do not have too many weight-2 columns (p. 581).

*Intuition note:* Each trellis alone sees the channel evidence and one set of parity checks. Passing its beliefs to the other trellis lets each use constraints it cannot see itself. Stopping when the two sets of best edges agree is a cheap sign that the beliefs have settled.

### 48.5 Parity-check matrices (p. 581)
Convention: the $N$ bits of a block are the $N/2$ bits $t^{(a)}$ followed by the $N/2$ bits $t^{(b)}$. Exercise 48.3 asks for a proof that a rate-1/2 convolutional code has a low-density parity-check matrix (Fig. 48.11a). A turbo code's parity-check matrix is obtained by listing the constraints of its two trellises (Fig. 48.11b), so turbo codes are also special cases of LDPC codes. A punctured turbo code need not have a low-density matrix, but it always has a sparse *generalized* parity-check matrix (explained in the next chapter) (p. 581).

**Further reading:** Johannesson & Zigangirov (1999) on convolutional codes and on sequential decoding, which explores only promising trellis paths and backtracks; it is used when the trellis is too big for min–sum. Frey (1998) on sum–product in turbo codes and the stopping criteria (p. 581).

## Toy example (ours, not from the text)
Take $k=2$ with state $(z_2,z_1,z_0)$ and taps $g^{(a)}=101_2$, $g^{(b)}=111_2$. Then $p=z_2$, $t^{(a)}=z_2\oplus z_0$, $t^{(b)}=z_2\oplus z_1\oplus z_0$.

**Nonrecursive**, with $z_0=s$, $z_1$ and $z_2$ the previous two source bits. Input $s=1,0,0,0$:

| step | $(z_2,z_1,z_0)$ | $t^{(a)}$ | $t^{(b)}$ |
|---|---|---|---|
| 1 | (0,0,1) | $0\oplus1=1$ | $0\oplus0\oplus1=1$ |
| 2 | (0,1,0) | $0\oplus0=0$ | $0\oplus1\oplus0=1$ |
| 3 | (1,0,0) | $1\oplus0=1$ | $1\oplus0\oplus0=1$ |
| 4 | (0,0,0) | 0 | 0 |

The output is finite: $t^{(a)}=1,0,1,0$ and $t^{(b)}=1,1,1,0$.

**Recursive**, with $z_0=s'\oplus p$ (Eq. 48.2 with $t^{(a)}=s'$) and the same $t^{(b)}$. Feed it $s'=t^{(a)}=1,0,1,0$, starting from $z_2=z_1=0$:

- Step 1: $p=0$, $z_0=1\oplus0=1$, $t^{(b)}=0\oplus0\oplus1=1$.
- Step 2: state $(z_2,z_1)=(0,1)$, $p=0$, $z_0=0$, $t^{(b)}=0\oplus1\oplus0=1$.
- Step 3: state $(1,0)$, $p=1$, $z_0=1\oplus1=0$, $t^{(b)}=1\oplus0\oplus0=1$.
- Step 4: state $(0,0)$, $p=0$, $z_0=0$, $t^{(b)}=0$.

This gives $t^{(b)}=1,1,1,0$ with the same states and $z_0$ values as the nonrecursive run, as Eq. 48.3 says.

Now feed the recursive encoder the single-1 input $1,0,0,0,0,0,0$. Applying the same rules gives $t^{(b)}=1,1,0,1,0,1,0,\dots$. It never returns to zero, so the response is infinite, unlike the nonrecursive one.

## Concepts
- [[convolutional-code]] (new) — code made by passing a source stream through a linear shift-register filter with two output bits per input bit (p. 574)
- [[shift-register-state]] (new) — the $k$ memory bits $z_1\dots z_k$ of the filter; $k$ is the constraint length (pp. 574–575)
- [[systematic-code]] (new) — one output bit equals the source bit, so source bits appear unchanged (p. 575)
- [[recursive-encoder]] (new) — encoder with linear feedback into the register; named by an octal ratio (p. 576)
- [[impulse-response-finite-vs-infinite]] (new) — nonrecursive: finitely many ones out; recursive: infinite, periodic, period at most $2^k-1$ (pp. 576, 578)
- [[trellis-termination]] (new) — forcing the final state to zero, in Fig. 48.8 ($k=4$) four source bits become parity bits (p. 579)
- [[turbo-code]] (new) — constituent convolutional encoders joined by interleavers; decoded by iterating sum–product (p. 579)
- [[interleaver]] (new) — a $K\times K$ permutation matrix reordering source bits before an encoder (p. 579)
- [[puncturing]] (new) — dropping some parity bits to raise the rate (p. 580)
- [[error-floor]] (new) — flattening of the error curve below about $10^{-5}$ in random turbo codes, caused by low-weight codewords (p. 581)
- [[error-correcting code]] — the codes discussed here are convolutional and turbo codes, which have sparse (low-density, or generalized) parity-check matrices (p. 581)
- [[posterior-distribution]] — per-bit posterior from the sum–product (BCJR) algorithm (p. 578)

## Bridges (candidates)
- [same-math] Sum–product (forward–backward) on a trellis ↔ bayesian: posterior distribution of each hidden variable given observations — the bit posterior given channel likelihoods.
- [structural-analogy] Min–sum (Viterbi) most-probable path ↔ bayesian: MAP estimate versus full posterior — path cost is a negative log-likelihood under the binary symmetric channel.
- [structural-analogy] Iterative message passing in turbo decoding ↔ bayesian: sequential updating — each trellis's output becomes the other's input, multiplied by the channel likelihood.
- [structural-analogy] Impulse response of a linear-feedback shift register ↔ pseudorandom generators and cryptography (the text notes they use the same periodic sequences, p. 578).
